# 02. Customer (Company) Workflow — FACET CRM

In FACET, "customer" and "company" are synonymous. The database table is named `companies`. All UI references say "Company".

---

## Company Lifecycle

```
Created → Active → [Inactive | Blocked]
```

| Status | Meaning |
|---|---|
| `active` | Normal operating state. Appears in dropdowns and rep lists. |
| `inactive` | No longer pursued. Hidden from active views but preserved. |
| `blocked` | Explicitly excluded (e.g., bad debt, blacklist). |

---

## Creation

Every company is created via the `create_company_with_rep()` SECURITY DEFINER RPC. This atomically:
1. Inserts the company record
2. Inserts a `company_reps` row linking the rep as primary owner
3. Returns the new company UUID

**Never insert a company with a direct INSERT without going through this RPC.** A company without a `company_reps` entry is invisible to the assigned rep.

### Auto-generated fields on creation:
- `customer_code` — auto-generated by trigger: `CUST-00001`, `CUST-00002`, etc.
- `company_name_normalized` — Arabic normalization applied by trigger
- `status` defaults to `active`
- `created_at` / `updated_at` set automatically

---

## Rep Assignment

A company has one primary rep and optionally one shared rep. Assignment is managed via the `company_reps` junction table.

| Role in junction | Meaning |
|---|---|
| `primary` | Main owner. Appears in `companies.primary_rep_id` (cache field). |
| `shared` | Secondary access. Rep can see the company but is not primary. |

**From the Manager's side (company detail page):**
1. Manager opens `/dashboard/companies/{id}`
2. Scrolls to "Assigned Reps" section
3. Selects a rep from dropdown + role (Primary / Shared)
4. Clicks Assign
5. If assigning as Primary, `companies.primary_rep_id` is also updated

When a rep is assigned, they receive an in-app notification: "Company Assigned: [Company Name]"

---

## Company Detail View

Both manager (`/dashboard/companies/{id}`) and rep (`/rep/companies/{id}`) have detail pages with two tabs:

### Contacts Tab
Lists all contacts linked to this company. Both manager and rep can add contacts. Only manager can delete contacts.

Fields per contact: full_name (EN), full_name_ar (Arabic), title, phone, whatsapp, email, is_primary, notes

### Projects Tab
Lists all projects linked to this company. Read-only list — projects are created from the projects page, not here.

---

## Editing a Company

**Rep:** Can edit company name, type, region, source, source_detail, notes for their own companies. Cannot change status or assigned rep.

**Manager:** Can edit all fields including status and assigned rep.

**Edit auto-triggers:**
- `companies.updated_at` updated by `trg_customers_updated` trigger
- `companies.company_name_normalized` re-calculated by `trg_normalize_customer` trigger on every UPDATE

---

## Deletion

Only manager and super_admin can delete a company. Deletion cascades to:
- All contacts (`company_id` FK with CASCADE)
- All `company_reps` rows (CASCADE)
- All projects set to NULL on `customer_id` (SET NULL — projects are not deleted)
- All activities linked via `company_id` remain (no cascade — historical record kept)
- `duplicate_flags` rows cascade deleted

Deletion is irreversible. UI shows a confirmation dialog.

---

## Duplicate Resolution

When the manager resolves a duplicate pair:

| Classification | Outcome |
|---|---|
| **Shared** | Both company records remain. Both reps keep access. Both companies stay active. |
| **Conflict** | Manager resolves externally (e.g., by deleting one record and reassigning data). The flag is marked resolved. |
| **Not a Duplicate** (resolved) | Flag dismissed. Both companies remain active. |

The system never automatically merges company records.

---

## Bulk Import

The manager can import multiple companies at once via `/dashboard/import`. The import page:
1. Accepts a CSV file (comma or tab delimited)
2. Parses: company_name (required), company_type, region, source, notes
3. Validates values against canonical lists
4. Shows a preview with valid/invalid row indicators
5. Optionally assigns all imported companies to a single rep
6. Imports valid rows via `create_company_with_rep()` RPC
7. Shows per-row success/failure results

Template CSV available for download from the import page.
